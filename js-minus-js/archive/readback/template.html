How it works

The input uses a custom font. Its variable axis SCAN doesn't change any outline. Each value switches on a different set of OpenType substitutions. At SCAN = j, the shaper finds the glyph in column j and passes its code along, glyph by glyph, into a sentinel character that CSS adds to every line with ::after. The sentinel is (code − 31) px wide and sits after the text, so nothing visible moves. The bare first line gets its sentinel from ::before instead, with a kern that cancels its width.

Each line has an absolutely positioned probe whose height comes from anchor-size() on that line's sentinel. The probe is a size container, so 100cqh / 1px inside it is the code in column j.

--scan sweeps across the columns and back, one column per frame, and drives both the font axis and the readers. Every column has a latch, a registered --v that takes the live reading only while the scan is on its column. The rest of the time a 1,000,000-second transition-delay holds the old value. A @counter-style whose symbols are the 95 printable characters turns each code back into text.

The scan only covers the editor's width. A view timeline on a marker as tall as the editor is wide turns that width into a number, so short text is re-read faster than long text.

Why scan at all? A single box width carries about 25 bits of layout precision, roughly three characters. Scanning trades space for time: all lines are read in parallel, one column per frame.

Limits

Up to __L__ lines and __P__ columns. A change appears when the scan next reaches that column, a second or two for short text. Rich pasted HTML and characters outside U+0020–U+007E aren't read. If the first line is deleted entirely, an empty line can appear above the text. A caret parked at the very start of the first line jumps while that line is scanned, because its sentinel sits in front of the caret.
