# Browser bugs

Browser behaviour found while building the projects that looks like a bug. The user reviews the MREs and files the
reports; rules for adding entries are in the root `CLAUDE.md` ("Browser bugs").

An MRE is one self-contained HTML file: no dependencies, pass/fail visible without script (red means the bug), and a
closing comment with the observed results, the spec text and the likely cause. Serve the repo root
(`python3 -m http.server 8765 --bind 127.0.0.1`) and open `bugs/<file>`.
"Survey NN §x" is a section of the Chromium survey, `survey/chromium/NN-*.md`; its experiments are in
`survey/chromium/exp/`.

## Unconfirmed or not bugs

- **Style-container rules re-matched only for direct children** (css-physics, Chromium 141): not reproduced in 153; no
  report; Blink's code handles descendants. css-physics keeps names on every level anyway.
- **Transitions on `.bd` restart from the base value, not the running one** (css-physics HISTORY): against
  css-transitions-1; possibly [441221575](https://issues.chromium.org/issues/441221575). A minimal page didn't
  reproduce it; needs one before an MRE.
- **`.ts` timeline-scope wrappers inside `.rz` make the scene vanish** (css-physics): never reduced.
- **Fontations avar2 cost ~axes³** (Chrome 148, from another chat): no report found, unmeasured here. Probably fixed
  upstream (survey 06 §1.3): read-fonts made avar application O(n) instead of O(n²) (`73fd5ce`) and large-axis fvar
  normalization a sorted search (`78aa50d`); 155 ships both (read-fonts 0.43.3). Each new instance still normalizes
  three times.
- **`media` on `<link rel=compression-dictionary>` is ignored** (paint): spec gap; the keyword isn't in HTML yet
  ([whatwg/html#11620](https://github.com/whatwg/html/pull/11620)).
- **An `<object>` isn't re-fetched when a `display: none` ancestor is shown again** (js-minus-js `net/probe`): the
  letter of HTML's object element steps says otherwise. "The element changes from being rendered to not being
  rendered" re-runs them, and a not-rendered element jumps to "fallback", which says "Destroy a child navigable". So
  showing the ancestor again would fetch again. Chrome 153 keeps the nested frame while the ancestor is hidden and
  reuses it (`HTMLPlugInElement::AttachLayoutTree`, `html_plugin_element.cc:223`). Firefox 157 doesn't re-fetch
  either, and it fetches under a `display: none` ancestor from the start. WebKit (Playwright's 27.2) re-fetches on
  every show, and web developers reported that as a regression:
  [230688](https://bugs.webkit.org/show_bug.cgi?id=230688) (2021, still New). These steps are a known spec issue,
  [whatwg/html#2692](https://github.com/whatwg/html/issues/2692) (open since 2017). It calls the reload "really
  weird", says nobody needs it for web compat, and proposes matching the majority. That makes this a spec question,
  not a Chrome bug. No WPT test covers showing the ancestor again; `object-in-display-none-load-event.html` covers only
  the load event.
- **~7,700 in-flight requests fail without retry** (paint): `kMaxOutstandingRequestsPerProcess = 2700`, then
  `ERR_INSUFFICIENT_RESOURCES`. A limit, not a bug.
- **Stale view timelines re-run style and layout in the same frame** (Chrome): specified (scroll-animations-1 §5.1).
- **Contenteditable Enter nesting, select-all + delete emptying the host, copy inlining author styles** (js-minus-js
  editor): long-standing editing behaviour, not researched.
- **HTTP/3: requests waiting for a stream are never retried** (Chrome, survey 08 §5): `CancelAllRequests` fails them
  with `ERR_CONNECTION_CLOSED`, and the retry path needs `IsConnectionReused()`; RFC 9114 §5.2 allows retrying requests
  the server never processed. The HTTP/3 twin of the `GOAWAY` row. Code only, no net log yet.
- **UA-internal ResizeObserver skips fire author-visible `error` events** (Chrome, survey 01 §5.3): the observer
  behind `contain-intrinsic-size: auto` shares the controller with author observers, so script-free pages get "loop
  completed with undelivered notifications" (60/s) and never idle. Needs script to observe; the RO spec's error is
  about author observers.
- **Scroll anchoring stays suppressed after an ancestor's `transform` animation has changed value, even through
  constant stretches** (Chrome, survey 04 §5 #8; `survey/chromium/exp/04/scroll/anchor2.html`, `anchor3.html`):
  measured; the suspected cause (the `transform_changed` diff for animated transforms) is unconfirmed.
- **Counter text lags a `counter-set` set inside a size-container recalc** (Chrome, survey 06 §5.3): `UpdateCounters()`
  doesn't run in `UpdateStyleAndLayoutTreeForSizeContainer`, so the text updates only in the post-layout pass; with two
  dependent levels the painted frame is stale. css-lists doesn't define frames: an inconsistency (`content: if()`
  updates at once), not clearly a spec violation.
- **SMIL instance times from syncbases and events are never pruned** (Chrome, survey 04 §5 #10;
  `survey/chromium/exp/04/smil/m.html`): ~1.5 MB/s at 10 µs periods. Memory growth, not a spec violation.
- **Behind test flags only** (Chrome; MREs when the flags move): `anchor-size(ident("--a" 2) width)` crashes the
  renderer with `CSSIdentFunction` (`ToQuery` reads the empty `Value()` of an `ident()`-backed name; survey 03 §5.5,
  09 §6.1); `@custom-media` parses but never applies, and its `cssText` drops the name (survey 09 §6.2); Blink ignores
  `hb_shape_full`'s result, so under `HarfRustShaping` a failed shape commits code points as glyph ids (survey 06 §5.1,
  07 §5).
- **`RoundHarfBuzzPosition` signed overflow without subpixel positioning** (Chrome, survey 06 §5.2): an advance
  ≥ 32,768 px saturates to `0x7FFFFFFF`, then `round(v / 65536.f) << 16` overflows (UB, in practice −32,768 px).
  Reachable with full hinting; code only (headless can't select it).
- Missing features, not bugs: Firefox `if()` ([1981485](https://bugzilla.mozilla.org/show_bug.cgi?id=1981485)); typed
  arithmetic before Firefox 158; scroll-driven animations default-on only from Firefox 159.
